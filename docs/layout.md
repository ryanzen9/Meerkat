# Layout Guide

## Structure

┌────────────────────────────┐
│ Tabs + Actions（固定） │
├────────────────────────────┤
│ │
│ Main Content（可滚动） │
│ - Chat / Files / History │
│ │
├────────────────────────────┤
│ Input + Actions（固定） │
│ Git 摘要单行 │
└────────────────────────────┘

1. Tabs + Actions（高度约 40px，固定）

左侧：Chat / Files / History 标签
右侧：刷新按钮 + 设置图标（独立于 tablist）
设置菜单：ChatGPT 账户、登录 / 登出、添加 / 切换账户，以及扩展设置、会话历史和导出操作

Tab 1：Agent Chat Windows（默认）

标准聊天消息流（Agent 与用户）
Agent 消息用浅色气泡，用户消息用深色
空白会话问候语前显示 Meerkat 图标
支持代码块（可横向滚动）。 代码块可包含语法高亮。右上角通常有「复制」，「打开」按钮。
消息中可能包含文件引用，使用蓝色下划线进行标记。经工具核实的引用与完整代码快照按对话保存；刷新或扩展重启后可继续打开，文件已变更或删除时打开原始只读快照，并恢复已保存意见的代码标注和解决状态。取消或失败保留引用，删除对话时一并清理。

输入框下方只保留一行 Git 摘要：分支（等宽字体，过长时截断）+ Git 状态 + 新增 / 修改 / 删除数量。
单行 `whitespace-nowrap`，不换行、不撑高输入区；拖窄侧栏时先截断分支名。

审查轮的意见卡片由 `submit_review` 成功回执渲染，按对话保存并恢复。卡片显示“未解决 / 已解决”，提供状态切换按钮；保存期间禁用按钮，失败时保留原状态并允许重试。原生 CommentThread 标题栏提供“归档批注”，保存后从编辑器移除该意见的所有批注；卡片、解决状态和代码快照继续保留，卡片提供“恢复批注”入口。归档与解决状态独立，刷新或重启后仍保持归档。状态与模型审查运行状态独立，切换不会发起模型请求或改变收录数量；对话导出包含当前问题状态。

Tab 2：Files

- 顶部单行：仓库 / 文件夹名（多仓库时可切换）+ 分支名 + Git 状态 + 新增 / 修改 / 删除计数
- Changes 与 Staged Changes 两组可折叠，标题右侧分别提供批量暂存、取消全部暂存按钮；每行可点击打开文件，右侧 `+` 暂存、`−` 撤回暂存，也支持在两组间拖放
- 底部固定提交区分两行：提交消息输入框独占一行、主操作按钮与取消上次提交入口同一行；只提交 Staged Changes，提交后主按钮切换为带未推送数量的推送按钮，重新暂存文件后可继续提交
- 未推送数量来自 Git，刷新后可恢复；推送前使用 VS Code 原生弹窗确认仓库、分支、远程目标及提交数量，取消或关闭不推送。撤销仅针对最后一次未推送提交，改动恢复到暂存区，现有文件内容保持不变
- 提交消息按仓库隔离，失败保留；提交期间禁用该仓库的暂存按钮和拖放，未解决冲突时禁用提交
- 不再显示「与 Source Control 同步 · 点击文件打开」提示

Tab 3：History（可选）

会话历史列表
点击后跳转至 Tab 1（Agent Chat Windows） 展示历史会话记录

2. Input + Actions（底部固定）

输入框（单行或多行自适应，高度约 36–48px）
Placeholder：「Ask the agent…」或「询问这个 diff…」
右侧发送按钮（小图标）
输入区不再提供「交互模式」选择：每轮是否进入审查由 Host 在开始前自动判定，前端不发送或保存该状态。
输入框下方的 Git 摘要行与「Enter 发送 · Shift+Enter 换行」提示、新建会话按钮同属固定底部区域，滚动内容不会推动它们。
